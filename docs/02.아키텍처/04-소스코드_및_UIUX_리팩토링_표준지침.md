# [REF-STANDARD] 범용 소스 코드 및 UI/UX 리팩토링 표준 지침

> **문서 ID**: `020004` (`docs/02.아키텍처/04-소스코드_및_UIUX_리팩토링_표준지침.md`)  
> **버전**: v1.0  
> **수립 일자**: 2026-11-22  
> **관리 주체**: MoaBogo Core Architecture & Tech Lead Team  
> **적용 범위**: 프론트엔드(`src/`) 및 백엔드 전역 소스 코드 구현 및 리팩토링 후처리  

당신은 소프트웨어 아키텍트이자 프론트엔드/백엔드 테크 리드입니다.
제공된 소스 코드를 분석하고, 다음 **7대 설계 원칙과 가드레일**에 따라 **단계적이고 무손실(Zero-Loss & Zero-Regression)** 리팩토링을 수행하십시오.
기존 비즈니스 로직의 동작과 외부 인터페이스(Props/Events)를 100% 무결하게 보존하되, 유지보수성과 확장성, UI 완성도를 극대화해야 합니다.

---

## 1. 도메인 책임 및 역할 기반 분리 (Domain-Driven Responsibility)

- **도메인 격리**: 서로 다른 성격의 비즈니스 도메인 로직을 단일 모듈이나 파일에 혼재시키지 않는다.
- **성취(Metric) vs 이행/준수(Compliance) 분리**:
  - 진도율·달성률(%) 중심의 데이터 모델과 주기적 기한·증적(Proof) 관리 로직은 별도 서비스 계층으로 분리한다.
- **회계/데이터 분류 무결성 (Anti-Double Counting)**:
  - 계좌 간 내부 이동/대체 전표(`TRANSFER`)와 순수 소비 지출(`EXPENSE`)을 엄격히 구분하여 통계 왜곡을 원천 차단한다.

> **💡 모아보고 적용 사례 (Sample)**:
> - **Before**: `GoalService` 내부에 운동 달성률과 함께 알뜰폰 6개월 만기일, 세금계산서 발행 체크까지 혼재.
> - **After**: 달성률 중심의 `MoaGoal`과 정기 계약·증적 중심의 `MoaRoutine`으로 도메인 분리. 루틴 정기이체 시 지출이 아닌 `TRANSFER` 타입으로 처리하여 당월 총지출 통계 왜곡 방지.

## 2. 객체지향 설계 및 클린 아키텍처 (OOP & Clean Architecture)

- **단일 책임 원칙 (SRP) 및 코드량 상한선**:
  - UI 렌더링 컴포넌트는 오직 '화면 표현'만 담당한다. 데이터 페칭, 유효성 검사, 상태 전이 계산은 컴포넌트 밖(커스텀 훅, 서비스 클래스)으로 추출한다.
  - **정량 기준**: 단일 UI 컴포넌트 파일이 400~500줄을 초과할 경우 비즈니스 로직 훅(`useXXX.ts`) 및 서브 뷰 컴포넌트로 분리한다.
- **비즈니스 엔티티 캡슐화**: 도메인 핵심 상태와 계산 규칙(유효기간 계산, D-Day 산출, 상태 전이 조건)은 도메인 모델 내부 메서드로 응집한다.
- **의존성 역전 원칙 (DIP)**: 외부 인프라(로컬 엔진 vs 클라우드 API, LocalStorage vs IndexedDB)에 대한 직접 참조를 제거하고, 공통 인터페이스(`IProcessor`, `IStorageAdapter`)를 통해 주입받도록 리팩토링한다.

> **💡 모아보고 적용 사례 (Sample)**:
> - **Before**: `MvnoCard.tsx` 내부에서 만료 D-Day 계산, IndexedDB 저장, OCR 파싱 함수를 직접 선언하고 실행.
> - **After**: UI는 `MvnoCard.tsx`, 비즈니스 계산 및 상태는 `useMvnoRenewal()` 훅, 저장은 `IOfflineStorage` 인터페이스로 격리.

## 3. 디자인 패턴 적용 및 오버엔지니어링 방지 (Design Patterns & YAGNI)

- **FSM (유한 상태 머신, Finite State Machine)**:
  - 단계별 상태 및 라이프사이클이 3단계 이상이거나 전이 규칙이 엄격한 경우 명시적인 FSM 전이 테이블 또는 State 패턴으로 대체한다 (단순 2단 boolean 토글에는 적용 금지).
- **전략 패턴 (Strategy Pattern)**:
  - 결제/송금 방식, 외부 알림 채널, 다양한 서브 위젯 렌더링 등 향후 3개 이상의 확장이 예정된 분기 로직은 인터페이스 기반의 전략 맵으로 구성한다.
- **멱등성 보장 트랜잭션 (Idempotency Pattern)**:
  - 결제, 상태 확정, 데이터 이관 등 중복 실행 시 위험이 있는 액션에는 고유 멱등성 키(`UUID` 또는 주요 인자 기반의 `SHA-256 Hash`)를 생성하여 DB 레벨 중복 등록을 차단한다.

> **💡 모아보고 적용 사례 (Sample)**:
> - **Before**: `if (days < 0) ... else if (days < 4) ...` 형태로 알뜰폰 만기 단계와 UI 색상을 매번 인라인 분기.
> - **After**: `MvnoStatusFSM` 정의 (`NORMAL` ➔ `NOTICE` ➔ `IMMINENT` ➔ `URGENT` ➔ `OVERDUE`). 정기이체 완료 시 `SHA256(routine_id + due_date + amount + accounts)` 해시 키로 PostgreSQL `UNIQUE` 제약 검증.

## 4. 디자인 시스템 토큰화 및 완전 바인딩 (Design System Tokens)

- **임의 스타일링 배제**: 하드코딩된 인라인 스타일(`style={{...}}`)이나 임의의 폰트/색상 클래스를 금지하고, 표준 토큰 시스템(`ELM-*`)을 바인딩한다.
- **공통 컴포넌트 규격 준수**:
  - 헤더/타이포그래피, 상시 삭제(Clear) 'X' 버튼이 내장된 입력필드, 색상별 상태 Pills 뱃지, 필터 칩, 계층 트리를 공통 원자 컴포넌트로 일원화한다.

> **💡 모아보고 적용 사례 (Sample)**:
> - **Before**: `<input className="border p-2" />` (입력값 초기화 버튼 누락).
> - **After**: `ELM-INP-01` 토큰 적용 (우측 `absolute right-2.5` 상시 노출 X 버튼 내장 컴포넌트로 일괄 교체).

## 5. 시각적 소음 제거 및 마이크로 인터랙션 (Noise Reduction & Floating Layers)

- **화면 설명문 다이어트**: 페이지 본문에 장황하게 나열된 설명, 주의사항, 가이드 텍스트를 과감히 제거한다.
- **물음표(`?`) 플로팅 레이어 (Tooltip / Popover)**:
  - 맥락 설명이 반드시 필요한 위치에는 16x16px 크기의 컴팩트한 `?` 아이콘 버튼을 배치한다.
  - 마우스 호버(데스크톱) 또는 탭(모바일) 시 1px 테두리와 은은한 그림자가 적용된 플로팅 레이어로 간결하게 정보를 제공한다.

> **💡 모아보고 적용 사례 (Sample)**:
> - **Before**: "알뜰폰 프로모션 만기 시 정상 요금이 부과되므로 사전에 번호이동을 신청하여야 합니다..."라는 3줄 텍스트가 카드마다 노출.
> - **After**: 텍스트 삭제 후 D-Day 뱃지 옆 `?` 아이콘 배치 ➔ 호버 시 "정상 요금 전환 전 위약금 없는 이동 권장" 플로팅 툴팁 표출.

## 6. 반응형 최적화 가드레일 (줄바꿈 정책 및 수직 정렬)

- **수직 100% 중앙 정렬 고정 (Mandatory Vertical Centering)**:
  - 버튼, 칩, 뱃지, 입력창, 수직 트랙 내부의 아이콘과 텍스트는 1px 오차 없이 완전 수직 중앙(`items-center`, `valign: center`)에 고정한다.
- **요소 내부 줄바꿈 금지 (`whitespace-nowrap`)**:
  - 버튼 레이블, 칩 텍스트, Pills 뱃지, 탭 라벨 내부 텍스트는 뷰포트가 좁아져도 줄바꿈을 절대 금지하며, 넘칠 경우 `truncate`로 처리한다.
- **요소 간 줄바꿈 적용 (`flex-wrap` / Responsive Grid)**:
  - 뷰포트 크기 축소 시 텍스트가 깨지는 대신 **컴포넌트 단위**로 아래 줄로 자연스럽게 스태킹되도록 `flex flex-wrap gap-2` 또는 반응형 그리드(`grid-cols-1 md:grid-cols-2 lg:grid-cols-3`)를 적용한다.
- **이벤트 버블링 격리**: 카드 클릭과 내부 액션 버튼 간 충돌을 방지하기 위해 내부 핸들러에 `e.stopPropagation()`을 필수 적용한다.

> **💡 모아보고 적용 사례 (Sample)**:
> - **Before**: 모바일 화면에서 "⏳ 갱신\n임박"처럼 뱃지 내부 텍스트가 두 줄로 깨져 레이아웃 높이가 불규칙해짐.
> - **After**: 뱃지 내부에 `whitespace-nowrap`을 강제하고, 카드 상단 액션 바 전체에 `flex-wrap`을 적용하여 뱃지와 버튼이 통째로 자연스럽게 정렬되도록 개선.

## 7. 프론트엔드/백엔드 공통 안정성 및 무손실 검증 가드레일

- **무손실 회귀 방지 (Zero-Regression Guarantee)**:
  - 리팩토링 전후 컴포넌트의 외부 인터페이스(Props 타입, 콜백 파라미터)는 100% 동일하게 유지되어야 하며, 리팩토링 직후 반드시 `npx.cmd tsc --noEmit` 검증을 통과해야 한다.
- **오프라인 우선 및 동기화 (Offline-First & Stale Guard)**:
  - 네트워크 단절 시 쓰기 작업은 로컬 큐(`IndexedDB`)에 저장하고 화면은 낙관적 업데이트를 적용하되, 외부 결제/인증 딥링크는 `disabled` 처리한다.
- **민감정보(PII) 마스킹**:
  - 전화번호, 계좌번호, 고유 식별자는 뷰 계층 렌더링 시 기본 마스킹 처리한다.
