## 📌 1. 데이터 표준 거버넌스 10대 핵심 원칙

모아보고(MoaBogo)의 모든 데이터베이스 객체와 데이터 흐름은 다음 10대 원칙을 단일 진실 공급원(SSOT)으로 준수합니다.

1. **표준 단어 기반 조합 원칙**: 모든 데이터 항목은 본 문서에 등록된 **표준 단어**의 조합으로만 구성하며, 임의의 동의어·금지어·비표준 축약을 금지합니다.
2. **표준 용어 및 풀-워드 도메인 원칙**: 용어는 `[수식 단어 + ... + 도메인 분류어]` 순서로 조합하며, AI 에이전트 추론 효율·토큰 절감·프론트엔드(`camelCase`) 직렬화 호환성을 극대화하기 위해 **자음 축약 약어 대신 표준 풀-워드 도메인 접미사**를 채택합니다.
3. **컬럼명 도메인 접미사 일관성 강제**: 시스템 메타 예외(7대 감사 컬럼)를 제외한 **모든 테이블 컬럼의 마지막 단어는 반드시 19대 표준 도메인 접미사 중 하나**여야 하며, 동일 도메인 접미사는 전 테이블에서 동일한 PostgreSQL 물리 타입을 보장합니다.
4. **PK 표준 (UUID v7 우선 & 업무별 복합키)**: 오프라인 우선(Offline-First) 환경의 클라이언트 선행 채번 및 B-Tree 인덱스 페이지 분할 방지를 위해 **시간순 정렬 가능한 UUID v7**을 기본 PK로 사용합니다. 다대다 매핑(`ledger_members`) 및 일자 집계(`ledger_daily_aggregations`) 등 식별 종속 관계에 한해 복합 PK를 허용합니다.
5. **물리 FK 원칙적 미사용 (Soft Reference)**: 오프라인 비순차 동기화, 미아 데이터(`UNALLOCATED`) 독립 보존, 게스트 `NULL` 참조 및 파티셔닝 유연성을 위해 물리적 `FOREIGN KEY`는 원칙적으로 생성하지 않습니다. 단, 생명주기가 100% 종속되어 `ON DELETE CASCADE`가 필수인 강한 종속 관계에 한해 근거를 명시하고 예외 적용합니다.
6. **인덱스 성능 의무화**: 물리 FK 미사용으로 인한 참조 조회 저하를 막기 위해 모든 논리 참조 키(`*_id`)와 주요 조회 조건에 B-Tree 인덱스를 의무화하며, 논리 삭제를 고려한 **부분 인덱스(`WHERE deleted_yn = FALSE`)**, `JSONB`용 **GIN 인덱스**, 벡터 검색용 **HNSW 인덱스**를 표준 적용합니다.
7. **7대 감사 컬럼 & Soft Delete 전수 적용**:
   - 전 테이블에 7대 감사 컬럼(`created_sys`, `created_at`, `created_by`, `updated_sys`, `updated_at`, `updated_by`, `version`)을 일괄 적용합니다.
   - **최초 등록(`INSERT`) 시에도 `updated_sys`, `updated_at`, `updated_by`를 `created_*`와 동일 값으로 반드시 함께 등록**하며, 수정(`UPDATE`) 시마다 PostgreSQL `BEFORE UPDATE` 공통 트리거(`fn_audit_update_stamp()`) 및 앱 레이어에서 `version = version + 1`과 `updated_*` 3종을 자동 현행화합니다.
   - 영구 감사 로그(`sys_audit_change_logs`, `sys_pii_access_logs`)를 제외한 일반 업무 테이블은 `deleted_yn` / `deleted_at` 기반 논리 삭제(Soft Delete)를 기본으로 합니다.
8. **목적별 `JSONB` 구성 원칙**: PostgreSQL의 바이너리 `JSONB` 타입만 허용(`JSON` 금지)하며, `JOIN`/`SUM`/`WHERE =` 빈번 컬럼(금액·일자·상태·참조ID)은 JSONB에 편입하지 않고 정식 정규 컬럼으로 추출합니다.
9. **목적별 `VECTOR` 분리 원칙**: `pgvector` 임베딩은 트랜잭션 테이블 비대화 및 홈서버 RAM 부담을 막기 위해 전용 임베딩 테이블(`ai_semantic_embeddings`)로 분리하고 HNSW 인덱스로 운용합니다.
10. **서비스 독립성 · 2-Tier 첨부파일 · 공통코드 통합 · OCR/변경이력/PII 보안**:
    - 공통코드는 `sys_code_groups` + `sys_code_details` 단일 체계로 통합 관리합니다.
    - 첨부파일은 공용 물리 파일 원장(`storage_file_objects`)과 업무별 독립 첨부 테이블(6종)로 2-Tier 분리합니다.
    - OCR 소스·추출텍스트·매핑이력(`ocr_tasks` + `ocr_extraction_results`), 중요 데이터 변경이력(`sys_audit_change_logs`), 개인정보 열람 감사(`sys_pii_access_logs`)를 정규 테이블로 운용합니다.

| 12 | `TIME` | `*_time` | `VARCHAR(10)` | `NULL` 허용 | 시각 문자열 (`HH:mm`, 일정 시작·종료 시각 등) |
| 13 | `AT` | `*_at` | `TIMESTAMPTZ` | `CURRENT_TIMESTAMP` | UTC 저장 타임스탬프 (발생일시, 제출일시, 만료일시 등) |

## 🧩 4. 표준 용어 사전 (Standard Term Dictionary)

> 조합 규칙: `논리 용어명 = 수식어 + 도메인 분류어` / `물리 컬럼명 = {단어}_{단어}_{도메인접미사}`

| 용어명 | 물리 컬럼명 (표준) | 조합 단어 | 매핑 도메인 | FE (camelCase) | 용도 및 적용 사례 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| 사용자ID | `user_id` | `user + id` | `ID` | `userId` | 전 도메인 회원 고유 식별자 |
| 소유사용자ID | `owner_user_id` | `owner + user + id` | `ID` | `ownerUserId` | RLS 소유권 격리 표준 키 |
| 닉네임명 | `nickname_name` | `nickname + name` | `NAME` | `nicknameName` | 화면 표시용 사용자 별명 |
| 이메일내용 | `email_text` | `email + text` | `TEXT` | `emailText` | 소셜/이메일 계정 주소 |
| 인증제공자코드 | `provider_code` | `provider + code` | `CODE` | `providerCode` | `KAKAO`, `NAVER`, `GOOGLE`, `EMAIL` |

## ⚙️ 5. 공통 메타 · 트리거 · 보안 · 첨부 · OCR 표준 규약

### 5.1 7대 감사 컬럼 + Soft Delete 구현 표준
모든 테이블은 아래 7대 감사 컬럼을 보유하며, `INSERT` 시에도 `updated_*` 3개 컬럼을 `created_*`와 동일한 값으로 반드시 동시 적재합니다.
```sql
-- 공통 7대 감사 컬럼 + Soft Delete 표준 블록
created_sys VARCHAR(50)  NOT NULL DEFAULT 'WEB_APP',
created_at  TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,
created_by  VARCHAR(100) NOT NULL DEFAULT 'SYSTEM',
updated_sys VARCHAR(50)  NOT NULL DEFAULT 'WEB_APP',
updated_at  TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_by  VARCHAR(100) NOT NULL DEFAULT 'SYSTEM',
version     INT          NOT NULL DEFAULT 1,
deleted_yn  BOOLEAN      NOT NULL DEFAULT FALSE,
deleted_at  TIMESTAMPTZ  NULL
```
- **DB 레벨 자동 현행화 트리거**:
  ```sql
  CREATE OR REPLACE FUNCTION aiagent.fn_audit_update_stamp()
  RETURNS TRIGGER AS $$
  BEGIN
      NEW.updated_at := CURRENT_TIMESTAMP;
      IF NEW.version = OLD.version THEN
          NEW.version := OLD.version + 1;
      END IF;
      RETURN NEW;
  END;
  $$ LANGUAGE plpgsql;
  ```
  *(주의: 영구 불변 감사 로그 `sys_audit_change_logs`, `sys_pii_access_logs`는 수정·삭제 불가 테이블이므로 `deleted_yn`/`deleted_at`을 두지 않고 `UPDATE/DELETE` 권한을 회수합니다.)*

### 5.2 공통코드 단일 통합 원칙 (`sys_code_groups` + `sys_code_details`)
- 공용코드와 서비스별 개별코드를 별도 테이블로 분리하지 않고 단일 2단 마스터 테이블로 통합 관리합니다.
- `sys_code_groups.domain_scope_code` (`COMMON`, `LEDGER`, `FINANCE`, `DUTY`, `GOAL`, `DAY`, `ROUTINE`, `CAR`, `SETTLE`)로 서비스 소속을 구분하고, `is_system_readonly_yn`으로 시스템 고정 코드와 사용자/관리자 확장 코드를 통제합니다.

### 5.3 첨부파일 2-Tier 분리 원칙 (서비스 독립성 + 스토리지 일원화)
- **하위 인프라 원장 (`storage_file_objects`)**: `sha256_hash` 중복 제거, `storage_tier_code` (`ACTIVE` ➔ 30일 후 `ARCHIVED` tarball 압축), `retention_until_at` TTL GC를 1곳에서 일원화 처리합니다. 업무 도메인 ID는 일절 보유하지 않습니다.
- **상위 업무별 독립 매핑 테이블 (6종)**: 각 도메인은 자신의 첨부 테이블(`expense_proofs`, `moa_duty_attachments`, `moa_goal_attachments`, `day_media_attachments`, `routine_attachments`, `vehicle_attachments`)을 독립 소유하며 오직 `file_id`만 단방향 참조합니다.

### 5.4 OCR 소스 · 결과 텍스트 체계화 원칙
- **소스 파일**: `ocr_tasks.source_file_id` ➔ `storage_file_objects.file_id` 참조 (`purge_source_after_ocr_yn` 지원).
- **추출 결과·라인칩·검수이력 (`ocr_extraction_results`)**: `OcrMemoBoardModal`의 줄 단위 칩 배열(`raw_lines_json`), 자동 감지 스니펫(`detected_snippets_json`), 사용자 최종 매핑 결과(`user_mapped_json`), 필드별 수정여부(`review_state_json`)를 보존하며, 추출 원문(`redacted_raw_text`) 저장 시 주민번호·카드번호 16자리·계좌번호 패턴을 정규식 자동 마스킹합니다.

### 5.5 중요 데이터 변경이력 (`sys_audit_change_logs`) & PII 6대 보안 원칙
- **변경이력 등급**:
  - **1등급(전수 기록, 5년 보존)**: `transactions`, `atomic_expenses`, `ledgers`, `ledger_members`, `moa_allowances`, `moa_loans`, `routine_card_settlements`, `user_accounts`, `system_governance_configs`, `sys_code_details`
  - **2등급(삭제·핵심 상태전이만 기록, 1년 보존)**: `moa_duties`, `moa_goals`, `vehicles`, `vehicle_logs`, `routines`, `day_diaries`
  - **3등급(제외)**: `offline_sync_queue`, `ocr_tasks`, `ledger_daily_aggregations`, `game_live_rooms`
- **PII 4등급 및 열람 감사 (`sys_pii_access_logs`)**:
  - **1등급(비가역 해시)**: 비밀번호(`Argon2id`), 세션/방장 토큰(`SHA-256`)
  - **2등급(AES-256-GCM + 키버전 `enc_v1:` + 마스킹)**: 계좌번호, 사업자번호, 차량번호판, ICCID, 전화번호, 보험증권번호, 개인 OCR Key. 마스킹 해제·복호화 시 반드시 `sys_pii_access_logs`에 열람 기록 적재.
  - **3등급(민감 생활·건강)**: 처방전 OCR 텍스트, 비밀일기(`private_yn`), 통화녹음, 사진 GPS EXIF ➔ 소유자 RLS 격리.
  - **4등급(소멸성 게스트)**: `guest_id` ➔ 만료 시 익명화·파기, 과거 데이터 소급 매핑 금지.
- **탈퇴 처리**: 회원 탈퇴 시 `users` 및 2등급 PII(`*_enc`)·세션·OCR 원본은 즉시 비가역 파기(Hard Delete)하고, 타인과 공유한 모임 가계부 거래 원장의 작성자 표시만 `'탈퇴한 회원'`으로 익명화합니다.
