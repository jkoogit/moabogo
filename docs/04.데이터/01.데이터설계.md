## 📌 1. 개요 및 아키텍처 구조

본 문서는 [00.데이터표준정의서.md](file:///d:/dev/workspace/git.jkoogit/moabogo/docs/04.데이터/00.데이터표준정의서.md)의 거버넌스 규약을 기반으로 모아보고(MoaBogo) 전 서비스의 물리 데이터 모델, 서비스 독립성 경계, 통합 ERD 및 인덱스·RLS 전략을 규정합니다.

### 1.1 v3.0 ➔ v3.1 핵심 개편 사항
1. **풀-워드 도메인 접미사 100% 표준화**: 전 테이블 비즈니스 컬럼을 `_id`, `_code`, `_name`, `_title`, `_text`, `_amount`, `_qty`, `_count`, `_rate`, `_yn`, `_date`, `_time`, `_at`, `_url`, `_json`, `_enc`, `_masked`, `_hash`, `_vec` 19대 도메인으로 통일했습니다.
2. **서비스 독립성(Zero Horizontal Dependency) 테이블 분리 완결**:
   - `moa_duties`에서 모아목표(`moa_goals`, `moa_goal_members`, `moa_goal_logs`)를 완전 분리했습니다.
   - `user_accounts`(본인 계좌)와 `external_partner_accounts`(외부 거래처)를 분리했습니다.
   - 모아루틴 4대 플러그인을 대칭 구조로 정비하여 `routine_medicine_drugs` 및 `routine_tax_clients`를 정규 분리했습니다.
   - 코어 개인설정(`user_settings`)과 확장 서비스별 설정(`user_service_preferences`), 영구 정산 이벤트(`standalone_events`)와 휘발성 실시간 게임 룸(`game_live_rooms`)을 분리했습니다.
3. **2-Tier 첨부파일 · OCR · 공통코드 · 벡터 · 감사이력 체계 완결**:
   - 단일 통합 공통코드(`sys_code_groups`, `sys_code_details`) 및 `pgvector` 임베딩(`ai_semantic_embeddings`)을 신설했습니다.
   - 공용 물리 파일 원장(`storage_file_objects`) + 6대 업무별 전용 첨부 테이블(`expense_proofs`, `moa_duty_attachments`, `moa_goal_attachments`, `day_media_attachments`, `routine_attachments`, `vehicle_attachments`)로 2-Tier 분리했습니다.
   - OCR 추출 원문·라인칩·검수이력(`ocr_extraction_results`), 중요 데이터 변경이력(`sys_audit_change_logs`), PII 복호화 열람 감사(`sys_pii_access_logs`)를 신설했습니다.

## 📋 3. 전체 51개 테이블 상세 컬럼 정의서

> **공통 표준 블록 (전 테이블 일괄 적용)**:  
> - **7대 감사 컬럼**: `created_sys`, `created_at`, `created_by`, `updated_sys`, `updated_at`, `updated_by`, `version` *(등록 시 `updated_*` 3종을 `created_*`와 동일 값으로 동시 등록, 수정 시마다 `version + 1` 및 `updated_*` 현행화)*  
> - **논리 삭제**: 감사 로그(`3.9`, `3.10`)를 제외한 49개 테이블에 `deleted_yn BOOLEAN DEFAULT FALSE`, `deleted_at TIMESTAMPTZ NULL` 일괄 적용.  
> - **FK 표기**: `[논리]` = 물리 FK 미생성 (Soft Reference), `[물리 CASCADE]` = 강한 생명주기 종속 예외 FK.

## ⚡ 4. 인덱스 · 벡터(HNSW) · 동시성(Trigger) · RLS 최적화 전략

1. **논리 참조(`Soft Reference`) 및 부분 인덱스(Partial Index) 표준**:
   - 물리 FK를 생략한 모든 참조 키(`owner_user_id`, `ledger_id`, `atomic_expense_id`, `file_id`, `ocr_result_id`)에 `WHERE deleted_yn = FALSE` 조건부 B-Tree 인덱스를 의무 생성합니다.
2. **도메인별 고빈도 복합 인덱스**:
   - 가계부·원장: `(ledger_id, txn_occurred_at DESC) WHERE deleted_yn = FALSE`, `(user_id, dirty_yn, aggregation_date)`
   - 모아데이: `(owner_user_id, start_date, source_type_code) WHERE deleted_yn = FALSE`, `GIN (keyword_tags_json)`
   - 모아루틴: `(owner_user_id, category_code, active_yn, d_day_target_date) WHERE deleted_yn = FALSE`
   - 모아부릉 3대 키 중복 대사: `(owner_user_id, (occurred_at::date), payment_method_code, txn_amount) WHERE deleted_yn = FALSE`
   - 감사·PII 로그: `(target_table_name, target_record_id, created_at DESC)`, `(target_user_id, created_at DESC)`
3. **벡터 HNSW 인덱스 (`pgvector`)**:
   - `CREATE INDEX idx_ai_embeddings_hnsw ON aiagent.ai_semantic_embeddings USING hnsw (embedding_vec vector_cosine_ops) WITH (m = 16, ef_construction = 64);`
4. **공통 Trigger 및 RLS**:
   - 51개 전 테이블에 `BEFORE UPDATE` 트리거(`fn_audit_update_stamp`) 바인딩으로 `updated_at` 및 `version + 1` 강제.
   - `sys_audit_change_logs`는 1등급 테이블 10종에 대해 `AFTER INSERT OR UPDATE OR DELETE` 감사 기록(민감 컬럼 제외 필터링).
   - 개인 소유 테이블 전수에 PostgreSQL Row-Level Security (`owner_user_id = current_setting('app.current_user_id')::uuid`) 적용.
