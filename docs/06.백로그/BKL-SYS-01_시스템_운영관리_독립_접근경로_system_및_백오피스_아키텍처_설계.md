# [BKL-SYS-01] 시스템 운영 관리 독립 접근 경로 (/system) 및 백오피스 아키텍처 구축

## 1. 도입 취지 및 배경 (Why)
- **현황 및 문제점**:
  - 현재 서비스는 `비회원(게스트)`, `로그인 사용자`, `사용자 설정` 서비스만 존재하며, 시스템 관리자가 서버 상태, Cloudflare 터널, EasyOCR 큐, PostgreSQL 연결 풀, 감사 로그 등을 모니터링하고 제어할 수 있는 공식적인 관리 경로가 전무함.
  - 관리자용 기능이 사용자 화면과 섞이지 않도록 완전히 분리된 URL 경로(`/system`)와 강력한 보안 가드레일이 필요함.
- **도입 필요성**:
  - 홈서버 및 클라우드플레어 환경의 특성상 리소스(메모리 2GB OOM, 100초 타임아웃, DB 장애)를 실시간 모니터링하고 장애 시 안전 모드로 전환할 수 있는 '중앙 관제 백오피스' 구축 필수.

---

## 2. 개요 및 요구사항 (Overview & Requirements)

### 2.1 기능적 요구사항 (Functional Requirements)
1. **독립 URL 접근 경로 확보 (`/system`)**:
   - 일반 앱 경로와 분리된 `https://domain/system` 또는 `?route=/system` 독립 라우팅.
   - `SYSTEM_ADMIN` 권한을 가진 계정만 접근 가능하며, 일반 사용자는 403 Forbidden 차단.
2. **시스템 운영 핵심 관제 대시보드 (`SCR-SYS-01`)**:
   - **인프라 헬스체크**: PostgreSQL 풀 사용률, Cloudflare Tunnel 응답 속도, 2GB 메모리 소진율.
   - **EasyOCR 비동기 큐 모니터링**: 대기 작업 수, 평균 처리 시간, OOM 방어 재시도 카운트.
   - **통합 가계부/머니 감사 로그**: 이중 계상 방지 검증, 불일치 데이터 보정 툴.
   - **시스템 전역 공지 및 긴급 점검 모드 스위치**: 홈서버 재기동 시 서비스 안내 배너 강제 송출.

### 2.2 비기능적 요구사항 (Non-Functional Requirements)
- **보안 격리**: 민감 인프라 설정은 일반 프론트엔드 번들에 노출되지 않도록 서버사이드 인증 필수.
- **가용성**: 메인 DB 장애 시에도 메모리 캐시 및 읽기 전용 상태로 백오피스 헬스체크 렌더링 유지.

## 3. 아키텍처 및 상세 설계 (Technical Architecture)

### 3.1 4대 서비스 영역 도메인 분리 맵
```
[모아보고 4대 서비스 레이어]
 ├── 1. 비회원 서비스: /guest (SCR-GNT-01) - 임시 정산, 룰렛, 사다리
 ├── 2. 로그인 서비스: /app (SCR-DSH-01 ~ SCR-MON-01) - 가계부, 당번, 머니
 ├── 3. 사용자 설정: /settings (SCR-SET-01) - 개인 알림, 계좌, OCR 키
 └── 4. 시스템 설정: /system (SCR-SYS-01) - [신설] 백오피스, 인프라 관제, 감사 로그
```

## 4. 단계별 작업 가이드 (Implementation Guide)
- **Phase 1**: `/system` 경로 분기 및 `SYSTEM_ADMIN` RBAC 가드레일 구현.
- **Phase 2**: `SCR_SYS_01_시스템운영관제.tsx` 화면 프레임워크 구축.
- **Phase 3**: 홈서버 헬스체크 및 OCR 큐 상태 모니터링 위젯 구현.
- **Phase 4**: 긴급 점검 공지 송출 및 세션 강제 종료/감사 로그 열람 기능 연계.
