## 1. 세션 개요 및 핵심 마일스톤

본 세션 0020은 모아보고(MoaBogo)의 **대시보드 위젯 토글접기 헤더 표준화(div1 모델 준용), 야간 테마(Dark/Dawn) 서피스 토큰 보정, 가계부(`SCR-LED-01`) 레이아웃 및 드래그휠 안정화, 그리고 모아당번 1~7번 핵심 라이프사이클(업무정의, 4대 순환/승인 정책, 카테고리 관리, 초대 수신함, 실적 피어 승인, 대신수행 및 가계부 지출 자동연계)**을 완결하기 위해 진행되었습니다.

### 주요 추진 목표 및 달성 내역
1. **위젯 토글접기 헤더 표준 수립 (`div1` 모델 준용 - [0020-01])**:
   - 메인 대시보드(`SCR-DSH-01`) 7대 모듈의 헤더 레이아웃을 좌측 `[아이콘 + 타이틀(개수) + 설명]`과 우측 `[업무/컨트롤 버튼군 + 토글버튼]` 구조로 완전 표준화.
   - 우측 정렬 일관성(`ml-auto self-end sm:self-auto shrink-0`)을 확보하고, `inbound_radar`(요청된 머니)의 대기 건수/금액 뱃지와 일괄 승인 버튼을 아코디언 토글 블록 내부로 완전 편입.
2. **야간 테마(Dark / Dawn) 부자연스러운 밝은 배경색 개선 ([0020-01])**:
   - 책꽂이 카드/목록 행(`div4`), 목표 챌린지 카드(`div2`), 활동이력 피드(`div3`), 게임 퀵런처(`div1`) 내의 `bg-slate-50`, `bg-white` 잔재를 전면 제거하고 다크 서피스 토큰(`dark:bg-zinc-900/60`, `dawn:bg-[#101e42]/60`) 적용.
3. **가계부 종합관리(`SCR-LED-01`) 화면 리뷰 및 UX 고도화 ([0020-01])**:
   - 사용자 관리 태그 영역의 `shrink-0` 제약을 해제하고 `flex flex-wrap`을 적용하여 뷰포트 축소 시 구역 이탈(Overflow) 원천 차단.
   - Level 1 2대 대축(`[장부작성]` vs `[분석]`)을 공통 `ElmSld03` 슬라이드드래그휠 컴포넌트로 래핑하여 마우스 드래그 및 세로 휠의 가로 전환 지원.
   - 분석 보고서 스냅샷 이력에 카드보기(`LayoutGrid`) / 목록보기(`List`) 아이콘 토글 바 구현 및 모바일 전용 카드 그리드 렌더링 확립.
4. **모아당번 1~7번 핵심 라이프사이클 구현 ([0020-02])**:
   - **업무 정의 재정립**: 당번(여럿이 함께 순환 완수하는 책임 미션) vs 목표(개인 성취를 공개하고 응원받는 마일스톤) 도메인 분리 및 상단 2열 비교 가이드 배너 탑재.
   - **사용자 관리형 카테고리 체계**: 시스템 기본 7종(청소, 주방, 분리수거, 회계, 돌봄, 운동, 독서) 외 사용자 정의 카테고리 등록/관리 모달 지원.
   - **4대 순환 정책 엔진**: `RANDOM`(랜덤), `NAME_ASC`(이름순), `BIRTH_DATE`(생년월일순), `AGE_WEIGHTED`(나이/기여도 가중치 순환 알고리즘 `calculateNextAssignee`) 완비.
   - **4대 완료 승인 정책**: `PEER_3_APPROVAL`(타인 3인 이상 완료 확인), `ADMIN_APPROVAL`(관리자 승인), `SELF_CONFIRM`(본인 확인 즉시 완료), `NO_APPROVAL`(승인 생략 자율 완결).
   - **참가자 권한 체계**: `ASSIGNEE`(순환 수행자) vs `VIEWER`(관람자) 분리 및 게스트 소멸성 원칙 기반 초대 링크 생성/공유.
   - **당번 초대 수신함**: 초대 대기 목록을 실시간 조회하고 1클릭으로 내 당번 목록에 편입.
   - **직교 3상태머신 가시화**: `progress_status`, `settlement_status`, `evaluation_status` 실시간 반영 및 타인 3인 이상 확인 승인 누적 시스템 구현.
   - **대신수행 및 가계부 보상 연계**: 특정인 지명 vs 전체 공개 선착순 요청, 보상(용돈/품앗이쿠폰) 설정, **가계부 지출 거래 자동 생성 옵션** 및 카카오페이/토스 간편 송금 링크 제공.

## 3. 핵심 문제 해결 및 기술 검증 (Troubleshooting)

### 3.1 샌드박스 비영속 환경에서의 Git 소스 충돌 원인 규명 및 방어
- **문제점**: 샌드박스 컨테이너 재기동 시 `.git` 디렉터리가 비영속으로 초기화되면서 로컬 작업 트리가 원격 `dev`의 최신 커밋 이력과 단절되어 Git 충돌(`fatal: not a git repository` 및 non-fast-forward)이 발생함.
- **해결책**:
  - `[ ! -d .git ] && git init -b dev ...`를 통해 샌드박스 Git 환경을 선행 복원.
  - 모든 작업 시작 전 `git fetch origin dev && git checkout -B dev origin/dev`를 강제 실행하여 로컬 작업 트리를 원격 HEAD와 100% 동일하게 일치시킨 후 기능 브랜치를 분기함으로써 충돌을 원천 차단함.

### 3.2 대신수행 완료와 가계부 금전관리 3대 원칙의 무결성 연계
- **문제점**: 대신수행 완료 후 용돈 보상이 지급될 때 가계부 데이터가 중복 계상되거나 타인의 사적 영역을 침범할 위험 존재.
- **해결책**:
  - 금전관리 3대 원칙(단일 귀속성, TRANSFER 1:1 페어링, 태깅 분리)을 준수하여, 대신수행 보상은 요청자의 개인 가계부(`type='PERSONAL'`)에 배타적으로 귀속되는 지출 거래로 생성하고 메타데이터 태깅(`tag_names: ['대신수행보상']`)으로 분리 기록하도록 구조화함.
