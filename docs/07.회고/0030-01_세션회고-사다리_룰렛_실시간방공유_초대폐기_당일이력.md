## 2. 주요 아키텍처 및 구현 성과

### 2.1 하이브리드 동기화 채널 엔진
- 동일 브라우저 탭 간에는 `BroadcastChannel`과 `localStorage` 이벤트를 활용하여 0ms에 가까운 초저지연 동기화를 보장했습니다.
- 서로 다른 PC, 스마트폰, 브라우저 환경 간에는 Node.js Express의 Server-Sent Events (SSE) 스트림(`GET /api/v1/games/rooms/:roomId/events`)과 REST 액션 브로드캐스트(`POST /api/v1/games/rooms/:roomId/action`)를 이중화하여 외부 서비스(Pusher, Socket.io 등)에 의존하지 않는 자체 경량 백엔드를 완성했습니다.

### 2.2 방장 전용 라이프사이클 및 초대 폐기
- 방장이 게임을 종료하면 서버에 `CLOSE_ROOM` 메시지가 전송되어 룸 상태가 동결됩니다.
- 신규 참여자의 유입은 완전히 차단되며, 기존 링크로 접근하는 사용자는 최종 결과만 확인할 수 있도록 하여 보안과 무결성을 확보했습니다.

### 2.3 당일 한정 공유 게임 이력 관리
- 불필요한 스토리지 누적을 방지하기 위해 오늘 날짜(`new Date().toISOString().slice(0, 10)`)에 종료된 게임만 `localStorage`에 자동 보관하도록 설계했습니다.
- 게스트홈 하단에 1건 이상 존재할 때만 아코디언 토글이 나타나며, 클릭 시 당시의 게임 결과를 그대로 복원하여 팝업으로 재조회할 수 있습니다.

## 3. 학습 및 반성 (Keep, Problem, Try)

### Keep (지속할 점)
- **Zero-Dependency 경량 실시간 아키텍처**: 무거운 웹소켓 라이브러리 없이 순수 SSE와 BroadcastChannel만으로 고성능 동기화를 구현하여 번들 크기를 최적화함.
- **오프라인 우선 및 SSOT 원칙**: 네트워크가 불안정한 환경에서도 로컬 스토리지 스냅샷을 통해 데이터 손실을 원천 방지함.

### Problem (발생했던 문제 및 한계)
- **AI Studio 샌드박스 도메인 특성**: `ais-dev-` 도메인은 구글 로그인 세션이 필수여서 시크릿 창 접속 시 403이 발생하고, `ais-pre-` 도메인은 Share 배포 전까지 404/Page not found가 발생하여 개발 중 테스트 안내가 필요했음.
- **참석자 권한 세분화 필요**: 참여자(Guest)가 상단 참여인원수, 매장연동, 가중치 등의 방 기본 규칙을 조작하지 못하도록 하는 엄격한 RBAC 가드레일이 후속 과제로 식별됨.

### Try (다음 세션 개선 과제)
- **BKL-LAD-02 백로그 분기**:
  1. 게스트 참가자 권한 제약 (상단 인원수, 매장, 가중치, 속도 슬라이더 읽기 전용화).
  2. 참가자 사다리 섞기 / 목표 섞기 실시간 브로드캐스트 전파 보강.
  3. 접속자 수(Presence) 세션 기반 고유 탭 카운팅 정밀화.
