## 2. 주요 아키텍처 및 구현 성과

### 2.1 참여자 RBAC 및 상호작용 격리
- 게스트로 접속한 사용자는 게임의 기본 규칙(참여 인원수, 당첨 인원수, 가중치 토글, 속도 슬라이더, 매장 메뉴 연동)을 변경할 수 없도록 읽기 전용 UI 토큰을 적용했습니다.
- 게스트 전용 안내 배너를 통해 방장이 게임을 시작하기를 안전하게 대기하도록 유도했습니다.

### 2.2 고유 TabId 기반 Presence 및 이탈 감지
- 동일 디바이스에서 여러 탭을 열거나 창을 닫을 때의 정밀한 상태 추적을 위해 `tabId` 기반 SSE 스트림 매핑을 적용했습니다.
- 탭 종료 시 `window.onbeforeunload`에서 `navigator.sendBeacon`을 통해 `/leave` 엔드포인트를 호출하고 SSE 연결 해제 훅과 결합하여 점유했던 자리를 즉시 방출하도록 구현했습니다.

### 2.3 `hostToken` 기반 권한 위조 원천 방어
- 방장 권한을 단순히 URL 쿼리 파라미터(`host=1`)로 판별하던 기존의 취약점을 제거하고, 서버에서 방 생성 시 암호학적으로 안전한 128비트 난수 토큰을 발급했습니다.
- 토큰은 방장의 `sessionStorage`에만 보관되며, REST 액션 릴레이 시 `x-host-token` 헤더로 검증하여 비인가자의 방 조작을 403 Forbidden으로 엄격히 거절합니다.

### 2.4 원자적 자리 점유 및 In-Game Lock
- 동시 찜하기 경합 상황에서 서버가 선착순 1명만 승인하고 후속 요청에 대해 `409 Conflict (SEAT_ALREADY_CLAIMED)`를 반환하도록 단일 원자성을 확보했습니다.
- 게임 애니메이션(`isLadderTracing`, `isSpinning`)이 재생되는 동안에는 메뉴 교체, 이름 변경, 자리 찜하기가 잠기도록 설계하여 SVG 렌더링 궤적 깨짐을 방지했습니다.

## 3. 학습 및 반성 (Keep, Problem, Try)

### Keep (지속할 점)
- **TDD/린트 무결성**: 모든 수정 단계에서 `lint_applet`과 `compile_applet`을 동시 수행하여 0-Error 유지.
- **백로그 분리 거버넌스**: 프론트/인메모리에서 즉시 해결할 보안 과제와 향후 분산 인프라(Redis/PostgreSQL) 연계 과제를 명확히 구분하여 기록.

### Problem (발생했던 문제 및 한계)
- 샌드박스 런타임 환경에 따라 터미널 환경변수(`GITHUB_TOKEN`) 주입 여부가 달라져 원격 Git 푸시 시 권한 오류가 발생할 수 있음을 확인.
- 이에 따라 `AGENTS.md`에 다중 환경 토큰 감지 계층을 명시하고 로컬 `dev` 커밋을 즉시 머지하여 코드 유실을 방어함.

### Try (다음 세션 개선 과제)
- **`BKL-LAD-03` 백로그 대응**: 홈서버 PostgreSQL 16 실제 원장 연동(`BKL-DATA-01`)과 함께 RDBMS 기반 방장 권한 영속화 및 Redis 분산 락 구축 검토.
