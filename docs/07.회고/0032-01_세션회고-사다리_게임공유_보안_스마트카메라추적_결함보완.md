## 2. 주요 아키텍처 및 구현 성과

### 2.1 스마트 카메라 추적 뷰포트 (Smart Camera Trailing Viewport)
- 사다리가 진행될 때 앵커(Tracer)가 화면 양쪽 벽(경계선)에 가려지지 않도록 다음 경로 포인트를 선제적으로 읽어 반 칸(0.5 step, 52px) 여유 공간을 유지하며 가로 스크롤을 이동시키는 알고리즘을 도입했습니다.
- 이동 시작 전 참가자의 출발 지점으로 선제 뷰포트 이동(`ensureTracerVisible(..., true)`)을 수행한 후 부드럽게 사다리 애니메이션이 시작되도록 개선했습니다.

### 2.2 한글 IME 조합 중복 입력 방지 및 실시간 동기화 (`MemberNameInput`)
- `isComposingRef`와 `isFocusedRef`를 분리하여 한글 조합 중에는 로컬 상태를 보존하고 조합 완료(`onCompositionEnd`) 및 영문/숫자 타이핑(`onChange`) 시 즉시 실시간 동기화(`UPDATE_MEMBER_DETAILS`)를 전파하도록 구현했습니다.

### 2.3 다자간 사다리 연속 플레이 및 카운트다운 타이머 정합성
- 주자 1이 도착한 후 멈추는 문제를 해결하기 위해 `LadderArrivalModal`에 3초 자동 카운트다운 타이머를 장착했습니다.
- 클라이언트 간 타이머 중복 실행 및 경합을 방지하기 위해 방장(`!isGuest`) 화면에서만 타이머를 트리거하도록 격리하고, 클로저 상태 오류를 방지하기 위해 `onProceed(memberIndex + 1)`로 명시적 인덱스를 전달하여 전원 완주까지 끊김 없는 연속 주행을 달성했습니다.

### 2.4 방 종료 시 완벽한 로컬 개인 모드 복귀 및 참가자 알림 UX
- 방장이 게임을 종료했을 때 URL 파라미터(`room`, `host`)를 안전하게 소거하고 상태를 완전 초기화하여 원래의 개인 모드 실행 버튼(`[사다리 타기]`, `[즉시 결과]`)으로 즉시 복귀시켰습니다.
- 게스트 화면에는 `isGuestCloseNoticeOpen` 인터랙션 팝업을 노출하여 최종 결과 확인 및 `[참여종료 및 혼자 게임 계속하기]`를 원클릭으로 선택할 수 있도록 배려했습니다.

## 3. 학습 및 반성 (Keep, Problem, Try)

### Keep (지속할 점)
- **사용자 피드백 기반 신속한 결함 교정**: 사용자의 세부 피드백(1-a ~ 2-i, 타이머 연속 실행)을 체계적으로 분류하고 우선순위에 따라 순차적으로 완벽히 조치함.
- **철저한 브랜치 동기화**: 매 태스크마다 `dev`, `stg`, `main` 원격 브랜치 커밋 SHA를 일치시켜 배포 불일치를 원천 차단함.
- **컴파일/빌드 0-Error 원칙**: TypeScript 무검사(`tsc --noEmit`) 및 프로덕션 번들링(`vite build`)을 통과한 코드만 반영함.

### Problem (발생했던 문제 및 한계)
- React 클로저 특성으로 인해 `handleProceedAfterArrival` 호출 시 이전 `arrivalPopup` state가 잡히거나 인덱스가 누락되는 현상이 발생하여 연속 주자 실행이 멈추는 결함이 있었음.
- 파라미터 기반 명시적 인덱스 전달 패턴(`onProceed(nextIdx)`)으로 해결함.

### Try (다음 세션 개선 과제)
- **사다리/룰렛 원격 게임 WebSocket/WebRTC P2P 검토**: 현재 SSE + HTTP POST 릴레이 방식을 장기적으로 저지연 양방향 통신 계층으로 업그레이드할 수 있는 기술 검토 진행.
