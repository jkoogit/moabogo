## 2. 주요 아키텍처 및 구현 성과

### 2.1 Ref 기반 채널 격리 및 원자적 이벤트 동기화
- `LadderGameZone.tsx`와 `RouletteGameZone.tsx`에서 `useEffect` 의존성 배열에 포함되어 있던 가변 상태를 모두 `useRef`로 분리해, 게임 진행 중 상태가 바뀔 때마다 SSE(`EventSource`)가 재연결되던 현상(기존 242회 반복)을 단건 연결로 안정화했습니다.
- 사다리 `전체 즉시 결과` 실행 시 `SHUFFLE_RUNGS`와 `PLAY_LADDER`를 분리 송신해 발생하던 HTTP 레이스 컨디션을 단일 원자적 `PLAY_LADDER (skipTrace: true)` 패킷으로 통합해 해결했고, `UPDATE_SPEED`를 방장 전용 액션으로 신설하여 대기·주행 중 배속 변경까지 참여자 화면에 즉시 반영되도록 했습니다.

### 2.2 60/120fps `requestAnimationFrame` 주행 및 지수 감쇠 카메라 엔진
- `ladderEngine.ts`에 `buildPolylineCurve`와 `samplePolylineAtDistance`를 도입해 기존 `6px` 정수 격자 + `setInterval(13~40ms)`의 주사율 비트 지터를 제거하고, 매 디스플레이 프레임(`dt`) 기반 연속 거리 보간으로 전환했습니다.
- CSS `scroll-smooth`로 인한 스크롤 지연, 방향 전환 시 `±42px` 시선 오프셋 급점프, `el.scrollLeft` 정수 픽셀 반올림 피드백을 모두 제거하여 지수 감쇠(`1 - Math.exp(-k * dt)`) + 2차 안전 여백 하드 클램핑으로 부드럽고 이탈 없는 카메라 추적을 완성했습니다.

## 3. 학습 및 반성 (Keep, Problem, Try)

### Keep (지속할 점)
- **Playwright 듀얼 브라우저(Host PC + Guest Mobile) 실환경 E2E 검증**: SSE 단건 연결 수, 403 건수, 주행 중 즉시결과·배속 변경 레이스, 60fps 프레임 샘플링(`outOfViewCount`)까지 정량 지표로 확인해 사각지대를 제거함.
- **원인 기반 리팩토링**: 카메라 끊김 문제를 단순 계수 튜닝에 그치지 않고 `setInterval` vs VSync, 정수 라운딩, CSS `scroll-smooth` 충돌까지 근본 원인을 규명해 해결함.

### Problem (발생했던 문제 및 한계)
- 워크스페이스 스냅샷 복원 직후 `.git` 디렉터리가 비어 있어 `git reset` 시 인덱스 정렬(`git reset origin/dev`)을 주의 깊게 선행해야 했음.
- 백로그 `BKL-LAD-03`(RDBMS/Redis 분산 락 및 CSPRNG 서버 권위 검증) 및 `BKL-DATA-01`(PostgreSQL 16 실 원장 테이블 연동)은 본 세션 범위를 초과해 이월됨.

### Try (다음 세션 개선 과제)
- **`BKL-LAD-03` 및 `BKL-DATA-01` 착수 검토**: 인메모리 게임 룸 저장소 및 샘플 원장 데이터를 PostgreSQL 16 실제 스키마와 영속화 파이프라인으로 확장.
- **모바일 실기기 GPU 합성 성능 모니터링**: 사다리 참여 인원이 10명 이상으로 늘어날 경우 SVG `polyline` 및 마커 렌더링 비용을 최소화하기 위한 SVG 메모이제이션(`React.memo`) 고도화 검토.
