## 2. 주요 구현 및 기술적 성과

### 1) 게이미피케이션과 비즈니스 도메인의 완전한 유기적 결합
- 기존 비로그인 게스트 홈(`SCR_GNT_01`)에 머물러 있던 일회성 게임(1/N 정산, 사다리, 룰렛)을 로그인 회원의 실제 모임 데이터와 결합시켰습니다.
- 게임 참가자를 번거롭게 일일이 입력하지 않고, 참여 모임(`우리집 가계부`, `2026 동창회 모임`, `개발팀 티타임`)을 선택하는 즉시 모임원들의 이름과 아바타가 사다리, 룰렛, 정산 참가자로 자동 주입됩니다.
- 게임 결과 역시 화면에만 머물지 않고, 사다리 결제 당첨자나 정산 결과가 나오면 **모임 가계부에 즉시 지출로 기안**(`GameToLedgerExpenseModal`)되고, 룰렛 벌칙이 나오면 **모아당번 과업으로 즉각 배정**(`GameToDutyAssignModal`)되는 실질적인 협업 생태계를 완성하였습니다.

### 2) FSD 기반 컴포넌트 재사용 및 상위 오케스트레이션
- 비회원 홈에서 철저히 검증된 하위 게임존(`LadderGameZone`, `RouletteGameZone`, `SettlementGameZone`)의 내부 코드를 중복 개발하지 않고, 상위 허브 화면(`SCR_GAM_01`)에서 로그인 세션 컨텍스트와 도메인 모달을 래핑하는 방식으로 아키텍처 결합도를 극도로 낮추었습니다.

### 3) 룰렛 게임존 안정화 및 중복 렌더링 결함 원천 해결
- 상위 허브와 하위 게임존 양쪽에서 중복으로 마운트되던 결과 팝업 구조를 단일화(`RouletteGameZone` 내부 단일 팝업으로 통합)하여 팝업이 2장 겹쳐 뜨는 결함을 해소하였습니다.
- 설정 항목 수 영역에 `[+]` 5개 확장 버튼을 추가하고, 참여 모임 선택 시 인원 왜곡을 방지하기 위한 `isItemCountDisabled` 가드레일을 적용하여 모임 인원 불변성을 완벽히 보장하였습니다.

### 4) 공통 디자인 토큰(`ElmRng01`)의 시각적 완성도 고도화
- 사용자 피드백을 수용하여 `ElmRng01`의 숫자 입력 필드를 우측 정렬(`text-right pr-2 font-mono`)로 통일하고, `+` 확장 버튼을 입력필드 앞에 배치하며, 라벨 부가 액션(`가중치 OFF` 등)이 라벨 옆에 나란히 오도록 레이아웃을 전면 정비하여 모아보고 전 화면에 일관된 UI 감각을 부여하였습니다.

## 3. 장애 대응 및 예외 방어 내역

1. **룰렛 가중치 불일치 방어**:
   - 신규 항목 추가 시 weight가 10으로 주입되던 반면 초기 멤버 생성 시 weight가 1로 주입되어 발생하던 10배 가중치 왜곡 버그를 발견하고, 모든 항목 생성 및 리셋 시 기본 `weight: 10`으로 전면 일원화하여 확률 공정성을 확보하였습니다.
2. **참여 모임 인원 불변성 가드 (`isItemCountDisabled`)**:
   - 모임 가계부나 당번 그룹을 선택한 상태에서 룰렛 슬라이더를 건드려 모임 구성원이 탈락하거나 가상 인원이 추가되는 도메인 불일치 문제를 방어하기 위해, 모임 선택 시 항목수 슬라이더를 비활성화하고 `🔒 참여모임 인원 유지` 뱃지를 표시하도록 가드레일을 구축하였습니다.
