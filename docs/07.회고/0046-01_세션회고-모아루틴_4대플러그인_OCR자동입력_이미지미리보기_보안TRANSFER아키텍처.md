## 2. 주요 구현 및 기술적 성과

### 1) 도메인 독립형 플러그인 아키텍처 (`pluginContract.tsx` & 4대 플러그인)
- 모아루틴의 4대 유형(약복용, 알뜰폰 번호이동, 세금계산서 발급, 급여카드정산)을 단일 거대 컴포넌트에 혼재시키지 않고 `src/sample/screen/routine/plugins/` 아래 4개 독립 플러그인 모듈과 공통 계약(`pluginContract.tsx`)으로 분리했습니다.
- 이를 통해 향후 신규 라이프 루틴(예: 독서 루틴, 차량 점검 루틴)을 추가할 때 코어 화면(`SCR_ROU_01_모아루틴.tsx`) 수정 없이 레지스트리 등록만으로 확장 가능한 OCP(개방-폐쇄 원칙) 구조를 확립했습니다.

### 2) 실전 증빙(약봉지·카드명세서·세금계산서·번호이동) OCR 자동입력 & 터치확인 UX (`routineOcrFields.tsx`)
- 실제 사용자가 첨부한 4종 증빙 이미지의 정보 구조를 분석하여 파일 첨부만으로 핵심 필드가 자동 입력되고 기존 입력값이 있으면 안전하게 병합되도록 구현했습니다.
- OCR로 채워진 항목은 `자동입력` 배지로 명확히 구분하고, 사용자가 각 필드를 터치·수정해 검수할 때마다 `자동입력 확인 N/M` 진척도가 실시간 갱신되도록 설계하여 자동화 편의성과 데이터 신뢰성을 동시에 확보했습니다.

### 3) OCR 이미지 인라인 & 드래그/리사이즈 팝업 미리보기 (`OcrImagePreviewer.tsx`)
- OCR 처리된 첨부 이미지에 미리보기 토글을 제공하여, 입력 폼을 벗어나지 않고 인라인 영역에서 즉시 확대/축소·패닝하며 원본 수치(결제금액, 조제량, 승인번호 등)를 대조할 수 있게 했습니다.
- 세밀한 대조가 필요한 경우 Portal 기반 대형 팝업 뷰어로 전환해 드래그 이동·모서리 리사이즈·프리셋(`S/M/L/최대`)·다중 이미지 전환을 지원하며, 이를 `docs/03.디자인/02-UI디자인정책-이미지.md` §2.4 공통 디자인 정책으로 명문화했습니다.

### 4) 보안 가드레일(`securityGuards.ts`) 및 가계부 `TRANSFER` 브릿지(`ledgerTransferBridge.ts`)
- USIM 번호·결제계좌·카드번호 마스킹, 허용 송금 딥링크 스킴(토스/카카오 등) 화이트리스트 검증, 첨부파일 MIME/크기 검증을 공통 가드레일로 분리했습니다.
- 급여·카드 정산 완료 시 가계부 원장에 자산이동(`is_asset_transfer = true`, `related_transfer_id` 1:1 페어링)으로 단방향 적재하여 모아보고 금전관리 3대 원칙(이중계상 원천 차단)을 완벽히 준수했습니다.

### 5) 공통 화면 UX 디테일 고도화
- **타이틀/컨텐츠 `div` 분리 정책** 및 **슬라이드드래그휠**을 새 루틴 등록 팝업의 루틴유형 선택 영역에 반영했습니다.
- **`ElmBsh01` 핸들 드래그 이동형 바텀시트**를 표준화하여 팝업으로 원본 화면을 가리지 않고 자유롭게 위치를 옮기며 대조 입력할 수 있게 개선했습니다.
- 약복용 플러그인의 `[+ 약품 추가]` 버튼을 목록 하단으로 재배치하여 추가 직후 하단에서 자연스럽게 입력을 이어가는 동선을 확보했습니다.
