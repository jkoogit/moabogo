## 2. 객체지향 프로그래밍(OOP) & 도메인 주도 설계(DDD) 관점 분석

### 2.1 도메인 주도 설계(DDD) 적용 사례
1. **유비쿼터스 언어(Ubiquitous Language)의 코드 반영**:
   - 가계부(`Ledger`), 동행원(`Co-runner`), 관람원(`Observer`), 모아당번(`MoaDuty`), 대신수행(`ProxyExecution`), 모아머니(`MoaMoney`), 요구머니/요청머니, 차용/대여(`MoaLoan`).
   - 서비스 기획서(PRD)의 용어가 프론트엔드 타입(`types.ts`)과 화면 컴포넌트(`SCR_*`)에 1:1로 정확히 투영되어 있습니다.
2. **소비 지출과 자산/부채 이동의 도메인 엄격 분리 (Bounded Context)**:
   - PRD 핵심 정책인 *"용돈 및 빌림 거래는 소비 지출 통계에서 원천 분리된다"*는 비즈니스 룰이 `SCR-DSH-01` 및 `SCR-LED-01` 도메인 화면에 인라인으로 캡슐화되어 있습니다.

### 2.2 객체지향(OOP) 및 SOLID 원칙 적용 현황
1. **단일 책임 원칙 (SRP - Single Responsibility Principle)**:
   - `MoaLogo.tsx`: 브랜드 로고 표시 및 테마별 텍스트 색상 결정 책임만 담당.
   - `ThemeContext.tsx`: 테마 상태 저장 및 브라우저 미디어 쿼리 감지 책임만 담당.
   - `Tokens.tsx`: 원자적 UI 요소의 렌더링 및 수직 중앙 정렬 레이아웃 책임만 담당.
2. **개방-폐쇄 원칙 (OCP - Open-Closed Principle)**:
   - `App.tsx`의 `screens` 배열: 새로운 화면(`SCR-NEW-01`)이 추가되어도 상단 네비게이션 드롭다운 코드를 수정할 필요 없이 배열에 객체만 추가하면 자동 렌더링되도록 설계됨.

## 3. 적용된 프론트엔드 디자인 패턴 (Design Patterns in Action)

### 3.1 Composite Pattern (컴포지트 패턴)
- `SCR-LED-01`의 `ElmTre01` 트리 컴포넌트:
  - 단일 노드(항목)와 복합 노드(카테고리 폴더)를 동일한 `TreeNode` 인터페이스로 재귀 호출 처리.

### 3.2 Strategy Pattern (전략 패턴)
- `ThemeToggle` 및 `ThemeContext`:
  - 테마 렌더링 전략(`light`, `dark`, `dawn`)을 런타임에 동적으로 교체하며, 컴포넌트들은 테마의 세부 색상 구현체를 몰라도 추상화된 테마 컨텍스트에 의존.

### 3.3 Facade Pattern (퍼사드 패턴)
- `App.tsx`:
  - 복잡한 13개 화면의 내부 상태와 모바일/태블릿 반응형 뷰포트 시뮬레이션, 오프라인 네트워크 감지 상태를 하나의 단순화된 인터페이스로 래핑하여 최상위에서 조율.

## 4. 디자인 화면 소스 구성 코드 리뷰 & 디자인 관리 방안

### 4.1 코드 관점의 코드 리뷰 (Code Review Points)
- **긍정적 요소**:
  - 한국어 화면 명칭(`SCR_DSH_01_로그인메인대시보드.tsx`)을 파일명에 사용하여 비개발자/기획자와의 소통 시 화면 식별 속도가 극대화됨.
  - 모바일 터치 타깃 44px+ (`min-h-[44px]`), 스위치 전체 행 클릭 등 인간공학적 접근성(Accessibility) 확보.
- **개선 대상 요소**:
  - `SCR_*` 화면 컴포넌트들이 `useState`로 자체 Mock 데이터를 각자 들고 있어, 실제 백엔드 API 연동 시 상태 관리 로직을 Custom Hook(`useLedger`, `useDuty`)으로 외주화해야 함.

### 4.2 코드 관점에서의 디자인 관리 방안 (Design Ops)
1. **Design Token Single Source of Truth**:
   - `Tokens.tsx` 내의 인라인 클래스들을 점진적으로 Tailwind 플러그인 또는 CSS 변수로 격상.
2. **Container-Presenter 패턴 적용**:
   - `SCR_*` 컴포넌트는 오직 화면 렌더링(Presenter)만 담당하고, API 호출 및 비즈니스 검증은 상위 `PageContainer` 또는 Custom Hook이 주입하도록 분리.
