## 1. 개요 및 요구사항 대비 구현 내역

본 태스크는 사용자의 화면 리뷰 및 UX/레이아웃 개선 요청에 따라, 산발적으로 구현되어 있던 상태바 조절기를 단일 표준 토큰 `ELM-RNG-01`로 통합하고, 사다리 게임 캔버스의 슬라이드 휠 이벤트를 영구 복원하였으며, 중복 래퍼로 인해 닫기 버튼이 2개 노출되던 빠른등록 모달들을 단일 레이어로 정돈하고 기능단위 플랫 열거(Flat Peer Sections) 레이아웃을 확립하였습니다.

### 1.1 핵심 요구사항 구현 매트릭스

| 영역 / 요구사항 | 사용자 요청 내용 | 구현 상세 및 검증 결과 |
| :---: | :--- | :--- |
| **1. 상태바 증감드래그휠 표준화 (`ELM-RNG-01`)** | 인원정산-인원수, 사다리-참여인원수 및 선택인원수 컨트롤 표준화 | • `Tokens.tsx`에 `ElmRng01` 표준 토큰 신설: 좌우 `[-]`/`[+]` 햅틱 버튼, `input[type="range"]` 드래그 슬라이더, 상하 휠 ±step 증감 및 배경 전파 차단(`stopPropagation()`), 숫자 직접 입력 input 내장<br>• `SCR_GNT_01`의 인원정산 인원수(`memberCount`, indigo), 사다리 참여인원수(`memberCount`, indigo), 사다리 선택인원수(`winnerCount`, rose) 3종을 `ElmRng01`로 전면 교체하여 조작감과 테마 일관성 100% 확보 |
| **2. 사다리 게임영역 슬라이드휠 복원 (`ELM-SLD-03`)** | 참가자아이콘~사다리~목표아이콘 휠 이벤트 미작동 원인 해결 | • `Tokens.tsx` 내 `ElmSld03` 내부 스크롤 div에 React 인라인 합성 이벤트 `onWheel` 핸들러(`e.currentTarget.scrollLeft += delta`) 직접 바인딩<br>• DOM 리스너 연결 타이밍과 무관하게 참가자 아이콘~사다리선~목표 아이콘 전 영역에서 마우스 휠 스크롤 100% 즉시 동작 보장 |
| **3. 빠른머니등록 레이어 및 헤더 정리 (`SCR_QCK_01`)** | 닫기 버튼 2개 및 이중 레이어 정리, 문서ID/제목/설명 요소화로 줄바꿈 최소화 | • `SCR_DSH_01`의 외부 껍데기 박스 및 `✕` 버튼을 제거하고, `SCR_QCK_01`을 단일 카드 모달로 일원화하여 닫기 버튼 1개화 달성<br>• `ElmTyp01` 수직 블록 대신 문서ID(`SCR-QCK-01` 뱃지) + 제목 + 설명을 `flex-wrap min-w-0` 인라인 원자 요소로 구성하여 불필요한 줄바꿈 최소화 |
| **4. 빠른수행등록 모바일 최적화 (`SCR_QCK_02`)** | 이중 레이어 제거, 상태머신 속성명 영문 모바일 숨김, 인증사진 프리셋 드래그휠 적용 | • 단일 모달 카드화 및 닫기 버튼 1개화<br>• 수행상태머신 3열 버튼에서 영문(`COMPLETED`, `SUBSTITUTE`, `ON_HOLD`)을 `hidden sm:inline` 처리하여 모바일에서 글자가 밖으로 삐져나오는(overflow) 현상 완벽 방어<br>• 인증사진 프리셋 버튼 영역에 `ElmSld03`을 적용하여 마우스 휠 및 좌우 드래그 지원 |
| **5. 전체 팝업 이벤트 전파 차단 (`stopPropagation`)** | 전체 팝업 속성에 이벤트 전파 제한 | • `SCR_DSH_01`의 퀵 사다리 모달, 퀵 룰렛 모달, 빠른 머니등록, 빠른 수행등록 모달의 백드롭 클릭 닫기 및 모달 내부 `onClick`, `onWheel`에 `stopPropagation()` 가드레일 전수 적용 |
| **6. 사용자맞춤설정 드래그휠 (`SCR_SET_01`)** | 설정저장 버튼 아래 설정메뉴에 슬라이드드래그휠 적용 | • `SCR_SET_01`의 설정 탭 메뉴를 `ElmSld03`으로 래핑하여 좁은 화면에서도 탭 목록이 마우스 휠과 터치/포인터 드래그로 매끄럽게 스크롤되도록 고도화 |
| **7. 기능단위 플랫 열거 레이아웃 (Flat Peer Sections)** | 영역 안에 영역 중첩 구조 대신 같은 레벨 열거 방식으로 관리성 향상 | • 깊은 중첩 구조(`div > div > div > div`)를 걷어내고 부모 카드 컨테이너 아래 각 기능 블록(`Header`, `Controls`, `Canvas`, `Actions`)을 동등한 형제(Peer) 레벨로 열거<br>• 여백 누적(Padding Compounding) 0% 달성 및 컴포넌트 독립성과 유지보수성 극대화 |
