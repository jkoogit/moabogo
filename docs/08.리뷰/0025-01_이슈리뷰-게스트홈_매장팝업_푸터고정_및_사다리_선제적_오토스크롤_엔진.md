## 2. 세부 구현 및 개선 내역

### 2.1. [보상작업 1] 매장 메뉴 선택 모달(`StoreMenuSelectModal`) 고정 푸터 분리
- **문제점**:
  - `isStoreOnly` 모드에서 '매장 연동 완료' 버튼이 스크롤 본문(`overflow-y-auto`) 최하단에 배치되어 있어, 메뉴 수가 많은 매장(메가커피, 스타벅스 등 10개 이상) 선택 시 사용자가 화면 끝까지 스크롤해야만 완료 버튼을 누를 수 있는 사용성 저하 발생.
- **해결 방안 (`LadderModals.tsx`)**:
  - 모달 레이아웃을 **1) 상단 헤더 (`shrink-0`)**, **2) 탭 전환 바 (`shrink-0`)**, **3) 스크롤 본문 (`flex-1 overflow-y-auto`)**, **4) 하단 고정 푸터 (`shrink-0 pt-3 border-t`)**의 4단 구조로 완전 분리.
  - 하단 푸터 좌측에는 현재 선택된 매장명과 카테고리 아이콘, 메뉴 개수 요약 뱃지를 상시 표시.
  - 하단 푸터 우측에는 탭이나 스크롤 위치와 무관하게 즉시 누를 수 있는 '닫기' 및 '매장 연동 완료' 액션 버튼을 고정 배치.

### 2.2. [보상작업 2] 사다리 선제적(Preemptive) 오토 가로 스크롤 엔진 고도화
- **문제점**:
  - 6~12인 다인원 사다리 진행 시 가로 폭(800~1300px)이 모바일 뷰포트(360~500px)를 초과함.
  - 기존에는 트레이서가 벽면에 부딪힐 때까지 기다렸다가 브라우저 내장 `scrollTo({ behavior: 'smooth' })`를 호출하여, 브라우저 스크롤 큐 충돌 및 취소 현상으로 인해 공이 화면 밖으로 벗어난 뒤 뒤늦게 쫓아가는 모양새(Lagging Chase)가 발생함.
- **해결 방안 (`LadderGameZone.tsx`)**:
  - `ensureTracerVisible(ptX, nextPtX?, immediate = false)` 카메라 추적 엔진 탑재.
  - **진행 방향 선제 시야 예측 (Look-Ahead Bias)**:
    - 사다리 가로줄(Rung)을 타고 이동할 때 다음 좌표(`nextPtX`)와의 편차를 계산하여, 진행 방향으로 최대 140px(또는 화면 폭의 25%) 미리 전방 시야를 선제 확보.
  - **실시간 스프링 댐핑 (Spring Lerp)**:
    - 브라우저의 무거운 smooth 애니메이션 대신 매 틱(20~50ms)마다 목표 스크롤 값과의 차이(`diff`)를 40%씩 전진 수렴(`el.scrollLeft += diff * 0.4`)시켜, 공이 사라지는 일 없이 항상 시야의 안전 영역(Safe Zone) 중심에 공을 위치시킴.
  - **주자 출발/도착 시 즉각 포커싱**:
    - 새 주자 출발 시(`startPt`) 해당 기둥으로 선제 즉각 포커싱(`immediate = true`)하여 끊김 없는 시각적 연속성 제공.
