## 1. 디자인 정책 현황 분석 (Current State Analysis)

### 1.1 현재 디자인 시스템의 장점 (Strengths)
1. **원자적 토큰(Atomic Tokens) 기반 정규화**:
   - `ELM-TYP-01`(타이틀), `ELM-INP-01`(입력필드), `ELM-STT-01`(상태뱃지), `ELM-FLT-01`(필터칩), `ELM-NAV-01`(바텀바) 등 14종의 공통 컴포넌트가 체계적으로 추상화되어 화면 전반에 일관된 레이아웃을 제공합니다.
2. **엄격한 수직 100% 중앙 정렬 가드레일 준수**:
   - `min-h-[36px]`, `leading-none`, `flex items-center`를 결합하여 모바일/PC 반응형 환경에서도 텍스트와 아이콘이 축에서 어긋나지 않도록 방어했습니다.
3. **3대 팔레트 체계의 성공적 분리**:
   - 주간(화이트), 야간(그레이), 여명(블루)을 명시적으로 분리하여, 사용자가 취향과 환경(주간 사무, 야간 저조도, 야간 집중)에 맞추어 선택할 수 있는 기반을 마련했습니다.

### 1.2 한계점 및 레거시 부채 (Limitations)
1. **CSS 오버라이드 의존성 (CSS Specificity Coupling)**:
   - 각 샘플 화면 컴포넌트 내부에 `bg-white`, `text-slate-900`과 같은 Tailwind 정적 클래스가 강하게 하드코딩되어 있어, 테마 변환 시 `src/index.css`에서 `!important` 오버라이드 규칙으로 강제 반전시키는 구조입니다.
   - 이는 유지보수 시 컴포넌트가 확장될 때마다 CSS 오버라이드 규칙을 계속 추가해야 하는 기술 부채를 유발합니다.
2. **CSS Custom Properties (CSS 변수) 추상화 부족**:
   - 색상 토큰이 `--color-bg-canvas`, `--color-surface-card`, `--color-text-primary`와 같은 시맨틱 CSS 변수 형태로 정의되지 않고, 클래스명 오버라이드에 의존하고 있습니다.

## 2. 전문성 기반 디자인 시스템 개선 방향 (Professional Improvements)

### 2.1 CSS 변수 기반 시맨틱 디자인 토큰 아키텍처 전환
컴포넌트 내부에서 하드코딩된 색상 클래스를 직접 쓰지 않고, **테마 컨텍스트에 따라 자동으로 값이 바뀌는 CSS 변수 계층**을 정의해야 합니다.

```css
/* 추천: CSS Variables 아키텍처 */
:root, html.light {
  --bg-canvas: #f8fafc;
  --bg-card: #ffffff;
  --text-primary: #0f172a;
  --text-muted: #64748b;
  --border-subtle: #e2e8f0;
  --accent-action: #4f46e5;
}

html.dark {
  --bg-canvas: #121214;
  --bg-card: #1a1a1e;
  --text-primary: #f4f4f6;
  --text-muted: #8e8e93;
  --border-subtle: #27272a;
  --accent-action: #3f3f46; /* 톤다운된 징크 그레이 */
}

html.dawn {
  --bg-canvas: #070d1e;
  --bg-card: #0d1b3a;
  --text-primary: #f0f6fc;
  --text-muted: #7dd3fc;
  --border-subtle: #1e3a6d;
  --accent-action: #1d4ed8;
}
```

### 2.2 WCAG 2.1 AA 명도 대비(Contrast Ratio) 정량 검증 자동화
- **배경 대비 4.5:1 기준 준수**:
  - 다크 모드 텍스트(`#f4f4f6`) 대비 딥 그레이 배경(`#121214`) 명도비는 **15.8:1**로 최고 수준 통과.
  - 앰버 경고 라벨(`#fbbf24`) 대비 카드 배경(`#1a1a1e`) 명도비는 **9.2:1**로 안전 범위 충족.
  - 추후 스토리북(Storybook) 또는 Lighthouse a11y 테스트를 CI 파이프라인에 도입하여 색각 이상자(색맹/색약)를 위한 대비율을 정량 검증하는 파이프라인 구축 권장.

## 3. 엔지니어를 위한 프론트엔드 디자인 시스템 학습 방향 (Learning Roadmap)

1. **디자인 토큰 스펙 (W3C Design Tokens Community Group)**:
   - 디자인 토큰을 JSON 스펙으로 관리하고 Figma 토큰과 연동하는 표준 워크플로우 학습 (`Style Dictionary` 라이브러리 활용).
2. **Radix Colors & Tailwind v4 CSS Theme Layers**:
   - Radix UI가 구축한 12스텝 시맨틱 컬러 스케일(1: 배경 ~ 9: 단색 솔리드 ~ 11: 고대비 텍스트)의 설계 철학 분석.
3. **마이크로 인터랙션 & 모션 디자인 토큰**:
   - `duration-200`, `ease-out`, 스프링 물리 애니메이션을 토큰화하여 페이지 전환 및 모달 팝업의 일체감 극대화.
