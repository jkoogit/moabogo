# 모아보고(MoaBogo) 스마트 라이프 서비스: 모아목표 & 모아루틴 마스터 기획·설계 검토 보고서

## 1. 기획 배경 및 서비스 그룹 재구조화

모아보고(MoaBogo) 스마트 가계부 및 라이프 지원 플랫폼은 개인과 모임의 자금 흐름뿐만 아니라, 일상속 다양한 과업과 목표를 유연하게 통합 관리하는 것을 목표로 한다. 초기 기획 단계에서는 '모아목표' 서비스 내에 운동, 저축, 학습 외에 알뜰폰 번호이동, 세금계산서 발행, 급여일 정산 등 일상의 정기적 이행 과업까지 포함하는 방안이 검토되었다. 그러나 서비스가 구체화됨에 따라 목표 달성률(%) 중심의 서비스와 주기적 과업 유지보수(Routine & Compliance) 중심의 서비스 간 도메인 성격 차이가 명확해졌다.

이에 따라 시스템 전체의 사용성을 제고하고 상태 머신(State Machine)의 복잡도를 완화하기 위해, 서비스 그룹을 '모아목표(MoaGoal)'와 '모아루틴(MoaRoutine)'으로 도메인을 상호 분리하여 신규 도출하는 재구조화 작업을 단행하였다.

### 1.1 도메인 정체성 및 서비스 역할 분리

두 서비스 그룹은 사용자에게 요구되는 행동 양식과 상태 전이 논리에서 본질적인 차이를 보인다. 모아목표는 진행률의 상승과 단기/장기 성취에 집중하는 반면, 모아루틴은 정해진 주기에 따른 누락 없는 이행과 증적 관리에 집중한다.

| 서비스 구분 | 핵심 도메인 정체성 | 주요 메커니즘 | 데이터 지표 및 상태 |
| :--- | :--- | :--- | :--- |
| **모아목표 (MoaGoal)** | **성취 및 진도 추적** (Target & Progress) | • 연속 달성(Streak) 및 캘린더 잔디밭<br>• 가계부 자동 연동 및 저축 누적<br>• 계층형 학습 마일스톤 트리 | • 달성률 (0% $\rightarrow$ 100%)<br>• D-Day 소진율 게이지<br>• 동행원(수행) / 관람원(조회) |
| **모아루틴 (MoaRoutine)** | **주기적 정기 과업 및 계약 이행** (Routine & Compliance) | • 알뜰폰 6개월 갱신 및 만료 알림<br>• 월말 세금계산서 발행 체크리스트<br>• 월 정기이체 & 급여 정산 체크 | • D-Day 임박/초과 상태 (Imminent/Overdue)<br>• 증적 캡처 갤러리<br>• 가계부 자산이동 (Transfer) 연동 |

## 2. 모아목표 (MoaGoal) 상세 UI/UX 및 기능 규격

모아목표(`SCR-GOAL-01`)는 사용자가 설정한 목표의 성격을 반영하여 공통 엔지니어링 레이아웃 기반 위에 3대 카테고리 전용 추적 위젯을 선택적으로 렌더링하도록 설계된다.

### 2.1 공통 레이아웃 및 역할 기반(RBAC) UI 규격

모아목표 화면 상단은 목표 타이틀과 전체 달성률 진행 바가 위치하며, 접속자의 권한(수행자 동행원 vs 조회자 관람원)에 따라 하단 스티키 액션 바의 인터랙션이 동적으로 전환된다.

```text
 ┌─────────────────────────────────────────────────────────┐
 │ [공통 헤더: ELM-TYP-01] 목표명 | D-Day | 역할 뱃지      │
 │ [공통 진행률] 전체 달성률 Progress Bar (ELM-STP-01)      │
 ├─────────────────────────────────────────────────────────┤
 │ 탭 바 (ELM-TAB-01): [📊 달성 트래커] | [📷 인증 갤러리]  │
 ├─────────────────────────────────────────────────────────┤
 │ [카테고리 전용 벤토 그리드 메인 영역]                   │
 ├─────────────────────────────────────────────────────────┤
 │ [하단 스티키 바] (동행원: 인증 등록 / 관람원: 응원 입력) │
 └─────────────────────────────────────────────────────────┘
```

* **목표 메타 헤더 (`ELM-TYP-01`)**: 목표 제목은 높이 100% 수직 중앙 정렬(`items-center`)되며, 우측에 `수행자(동행원)` ➔ Indigo 뱃지(`bg-indigo-50 text-indigo-700`), `조회자(관람원)` ➔ Slate 뱃지 (`bg-slate-100 text-slate-600`)가 표시된다.
* **동행원 (Performer) 하단 바**: `[📷 오늘 수행 인증하기]` 버튼 (`ELM-BTN-01`, `min-h-[44px]`) 클릭 시 `SCR-QUICK-EXEC` 인증 바텀시트를 슬라이드 업으로 호출한다.
* **관람원 (Spectator) 하단 바**: `[👏 응원 보내기]` 및 `[💬 피드백 작성]` 입력필드(`ELM-INP-01`)를 통해 1-Click 이모지 리액션(`🔥`, `👏`, `💪`)을 남길 수 있다.

### 2.2 카테고리별 전용 UI 위젯 스펙

3대 카테고리는 각각의 성격에 최적화된 시각적 위젯을 구속받는다.

1. **생활습관 · 운동 카테고리**:
   * **Streak Heatmap Grid**: 7x5 벤토 타일 형태의 월간 잔디밭. 완료일은 `Emerald-500`, 양해 보류일은 `Amber-400`, 미수행은 `Rose-100`, 미래일은 `Slate-100`으로 렌더링된다.
   * **주간 7일 트랙 (`ELM-SLD-01` & `ELM-FLT-01`)**: 월~일 요일별 칩 배열로, 완료 시 `✓` 아이콘 및 Indigo 컬러로 표시된다.
   * **인증 갤러리 슬라이더 (`ELM-SLD-02`)**: 좌우 이동 버튼이 결합된 수평 스크롤 트랙으로 최근 인증샷 섬네일을 노출한다.
2. **장기적금 · 자산 카테고리**:
   * **가계부 자동 연동 카드**: 연동 가계부 식별자 및 카테고리 태그(예: `[우리집 가계부] #청약저축`)를 매핑하여, 가계부 데이터 입력 시 목표 금액에 실시간 가산된다.
   * **저축 페이스 (Pace) 분석 카드**: 최근 3개월 평균 저축액 기반 목표 달성 예상일 자동 추정 및 `🟢 정상 페이스` / `⚠️ 지연 경고` 뱃지(`ELM-STT-01`)를 제공한다.
3. **자격증 · 학습 카테고리**:
   * **D-Day 소진율 게이지**: 목표 시작일부터 시험일까지의 총 일수 대비 현재 소진 일수를 게이지 바로 표시한다.
   * **학습 마일스톤 데이터 트리 (`ELM-TRE-01`)**: 계층형 접기/펼침 트리(`▼`, `►`) 구조로 대단원/중단원/세부 과제를 관리하며, 체크박스(`ELM-CHK-01`) 클릭 시 완료 상태 및 전체 진행률이 즉시 계산된다.

### 2.3 예외 처리, 수행 인증 및 상태 머신 (FSM)

목표 수행 중 결석 발생 시 스트릭 단절을 방지하기 위해 월 1회 제공되는 '스트릭 방어권' 칩(`ELM-STT-01 Amber`)을 사용하거나, 관람원 과반수 승인을 거쳐 `Amber-400(양해 완료)` 타일로 보존할 수 있다.

수행 인증 바텀시트(`SCR-QUICK-EXEC`)는 카메라 촬영 및 갤러리 선택 시 '2026.10.31 07:30 AM' 형태의 타임스탬프 워터마크를 자동 렌더링하며, 한 줄 소감 입력필드(`ELM-INP-01`) 제출 시 잔디밭 타일이 즉시 전환된다.

```text
 [목표 (Goal) 상태 머신]
 (생성) ──► [ACTIVE: 진행중] ──(D-Day 경과 & 100% 달성)──► [COMPLETED: 완수]
                 │
                 ├──(사용자 일시정지)──► [PAUSED: 보류]
                 └──(D-Day 경과 & 미달성)──► [EXPIRED: 기간만료]
```

## 3. 모아루틴 (MoaRoutine) 상세 UI/UX 및 기능 규격

모아루틴(`SCR-ROUTINE-01`)은 3대 정기 과업을 상단 탭(`ELM-TAB-01`)으로 스위칭하는 벤토 그리드 레이아웃 구조를 갖춘다.

### 3.1 3대 정기 과업별 UI 명세

```text
 ┌─────────────────────────────────────────────────────────┐
 │ [공통 헤더: ELM-TYP-01] 모아루틴 (MoaRoutine)           │
 ├─────────────────────────────────────────────────────────┤
 │ 탭 바 (ELM-TAB-01):                                    │
 │ [📱 알뜰폰 회선] | [📄 세금계산서] | [💸 정기이체/급여정산]  │
 ├─────────────────────────────────────────────────────────┤
 │ [선택된 탭 전용 벤토 그리드 메인 영역]                  │
 ├─────────────────────────────────────────────────────────┤
 │ [하단 스티키 바] `[➕ 신규 루틴/과업 등록]` (ELM-BTN-01) │
 └─────────────────────────────────────────────────────────┘
```

1. **과업 1: 알뜰폰 번호이동 만기 관리**:
   * **회선 카드 벤토 그리드**: 회선별(본인, 배우자, 자녀 등) 사용 요금제, 6개월 할인 약정 만료일, D-Day 카운트다운을 표시한다.
   * **D-Day 상태 뱃지**: D-7 이내는 `ELM-STT-01 Amber` (`⏳ 갱신 임박`), 만료 초과는 `ELM-STT-01 Rose` (`🚨 요금 폭탄 주의`)를 부착한다.
   * **번호이동 완료 처리**: `[⚡ 번호이동 완료 처리]` 버튼 클릭 시 신규 요금제 입력 및 개통 캡처 증적을 등록하며, D-Day가 6개월 뒤로 재설정된다.
2. **과업 2: 월말 세금계산서 발행 이력 관리**:
   * **월말 마감 D-Day 바**: 매월 말일 마감까지 잔여 일수를 진도 바로 시각화한다.
   * **거래처 체크리스트 (`ELM-TRE-01`)**: 거래처별 금액, 발행 상태, 국세청/홈택스 승인 캡처 증적 업로드 기능을 제공한다.
3. **과업 3: 월 정기이체 & 급여 정산 체크리스트**:
   * **정산 항목 체크리스트**: 카드값, 청약, 보험료, 용돈 등 필수 이체 항목 목록.
   * **3초 딥링크 지원**: 미이체 항목 클릭 시 카카오페이/토스 간편 이체 스키마를 호출하고, 완료 후 가계부 자산이동 데이터로 1-Click 자동 이관한다.

### 3.2 신규 루틴 등록/편집 바텀시트 (`SCR-ROUTINE-EDIT`)

`[➕ 신규 루틴/과업 등록]` 클릭 시 호출되는 바텀시트는 과업 유형 선택 칩(`ELM-FLT-01`), 루틴명 및 대상 정보 입력필드(`ELM-INP-01`), 약정 주기 선택 드롭다운(`ELM-SEL-01`), 사전 알림 시점 선택(1달 전/2주 전/1주 전/1일 전 Multi-Select 칩), 가계부 자동 연동 토글 스위치(`ELM-SWT-01`)로 구성된다.

## 4. 모아루틴 ↔ 가계부 (MoaLedger) 자산이동 연동 아키텍처

모아루틴에서 이행되는 정기이체 과업은 단순 지출이 아닌 '자산이동(Asset Transfer)'으로 처리하여 회계 정합성을 보장한다.

### 4.1 자산이동 도메인 원칙 및 SHA-256 멱등성 검증

급여 계좌에서 카드 결제 계좌로의 이체나 개인 계좌에서 그룹 계좌로의 이체는 총지출(Expense) 통계에서 제외되고 출금 계좌(-)와 입금 계좌(+)의 잔액만 대칭 변경된다.

중복 이관을 원천 차단하기 위해 아래 공식으로 클라이언트/서버 단에서 SHA-256 해시 키를 생성한다:

$$\text{transfer\_hash\_key} = \text{SHA256}(\text{routine\_id} + \text{due\_date} + \text{amount} + \text{source\_account\_id} + \text{target\_account\_id})$$

PostgreSQL 16 DB의 `ledger_transactions` 테이블 내 `idempotency_key` 유니크 제약 조건을 통해 동일 건의 중복 처리를 방지한다.

### 4.2 PostgreSQL 16 원자적 트랜잭션 SQL 스펙

```sql
BEGIN;

-- 1. 자산이동 트랜잭션 생성 (중복 시 스킵)
INSERT INTO ledger_transactions (
    transaction_id, ledger_id, transaction_type, 
    amount, source_account_id, target_account_id, 
    memo, proof_image_url, idempotency_key, created_at
) VALUES (
    'TX-20261031-001', 'LEDGER-GROUP-01', 'TRANSFER',
    701208, 'ACC-WOORI-01', 'ACC-KBCARD-01',
    '10월 KB국민카드 결제계좌 이체 (모아루틴 연동)', 
    'proof_transfer_1031.jpg', 'HASH-SHA256-VAL...', NOW()
) ON CONFLICT (idempotency_key) DO NOTHING;

-- 2. 출금 계좌 잔액 차감
UPDATE ledger_accounts 
SET balance = balance - 701208 
WHERE account_id = 'ACC-WOORI-01';

-- 3. 입금 계좌 잔액 가산
UPDATE ledger_accounts 
SET balance = balance + 701208 
WHERE account_id = 'ACC-KBCARD-01';

COMMIT;
```

### 4.3 3초 빅테크 딥링크 & 오프라인 대응 (`SYS-OFFLINE`)

이체 버튼 클릭 시 수신자/금액 정보가 인코딩된 스키마(`kakaopay://pay/money/to/bank...`, `supertoss://send?...`)가 호출된다. 복귀 후 캡처본이 업로드되면 EasyOCR/PaddleOCR 파이프라인이 이체 정보를 자동 파싱한다.

오프라인 상태일 경우 `IndexedDB` 내 `Pending_Routine_Queue`에 암호화 저장된 후, 온라인 재연결(`window.online`) 시 Batch Commit으로 서버에 동기화된다.

## 6. 단계별 시스템 구현 로드맵 및 실행 가이드라인

모아목표 및 모아루틴 서비스의 안정적 배포를 위한 4단계 실행 로드맵이다.

1. **Phase 1: 토큰 메타데이터 구축 및 쇼케이스 (`SMP-01`) 연동**:
   * `ui-tokens-metadata.json`에 `ELM-TYP-01`부터 `ELM-SLD-02`까지 14개 공통 토큰 데이터 정의.
   * `SMP-01` 라이브 쇼케이스 컴포넌트 구현 및 수직 중앙정렬(`items-center`), `whitespace-nowrap` 가드레일 시각적 검증.
2. **Phase 2: 모아목표 & 모아루틴 프론트엔드 UI 및 FSM 구현**:
   * `SCR-GOAL-01` 카테고리별 3대 위젯 및 동행원/관람원 역할 스위칭 구현.
   * `SCR-ROUTINE-01` 3대 정기과업 벤토 그리드 및 `SCR-ROUTINE-EDIT` 바텀시트 모달 개발.
3. **Phase 3: 가계부 자산이동 연동 & SHA-256 멱등성 백엔드 파이프라인**:
   * PostgreSQL 16 DB 트랜잭션 및 `idempotency_key` 멱등성 검증 로직 구축.
   * 3초 빅테크 딥링크(`kakaopay://`, `supertoss://`) 및 OCR 증적 이미지 자동 파싱 처리.
4. **Phase 4: PWA 오프라인 큐 (`SYS-OFFLINE`) 및 엔드-투-엔드 검증**:
   * `IndexedDB` 기반 `Pending_Routine_Queue` 및 온라인 재연결 시 Batch Commit 파이프라인 완성.
